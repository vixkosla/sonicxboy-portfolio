# Актуальная статистика портфолио

Страницы /stats/ и /en/stats/ формируются на сервере при открытии. Главные страницы
остаются статическими. Для серверных маршрутов используется @astrojs/vercel.

## Что входит в отчёт

- Только главные страницы портфолио: / и /en/ на sonicxboy.dev.
- Метрика: 28 полных дней, уникальные посетители за весь период, визиты,
  просмотры, визиты с переходом в мессенджер, источники, домены источников.
- Визиты за сегодня показаны отдельно: неполный день не сравнивается с полными.
- Google Search Console: показы, клики, CTR, средняя позиция, запросы и страницы.
  Фильтр page применяется ко всем запросам API, включая итоговые числа.
- Horus и другие страницы в этот отчёт не входят.

## Свежесть и ошибки

HTML отправляется с Cache-Control: no-store и CDN-Cache-Control: no-store.
Внутри процесса данные каждого провайдера кэшируются на пять минут; параллельные
запросы используют одно обновление. Холодный экземпляр сервера запрашивает API снова.

На странице указано время получения данных. Если API перестал отвечать, последний
сохранённый результат показан с предупреждением и его настоящей датой.
Ошибка подключения не превращается в успешный ноль.

Резервные JSON-снимки включаются при сборке. Их можно обновить перед выпуском:

    pnpm stats:refresh

Старые снимки без scope: portfolio-home-pages не используются: они могли включать
другие разделы. Google обновляет данные с задержкой, а последние доступные дни могут
быть неполными; страница показывает firstIncompleteDate, если Google его возвращает.

GitHub-расписание обновления JSON не требуется для работы живой страницы.
Секреты GitHub Actions не передаются в Vercel Functions: это отдельные окружения.

## Доступ к API

Локально секреты читаются из переменных окружения или из
~/.config/sonicxboy-stats/tokens.json и google-oauth.json.
При VERCEL=1 локальные файлы не читаются.

Для Vercel Production нужны переменные окружения:

- YANDEX_METRIKA_TOKEN
- GOOGLE_CLIENT_ID
- GOOGLE_CLIENT_SECRET
- GOOGLE_REFRESH_TOKEN
- GSC_SITE_URL — необязательно; по умолчанию sc-domain:sonicxboy.dev.

GOOGLE_ACCESS_TOKEN подходит для временной проверки, но не для постоянной работы:
он истекает. Секреты читаются только серверными модулями src/server/.
Их нельзя добавлять в PUBLIC_* или выводить в браузер.

## Однократное подключение Google

1. Подтвердить sonicxboy.dev в Google Search Console.
2. В Google Cloud включить Search Console API и создать OAuth client ID типа
   Web application.
3. Указать redirect URI: http://localhost:8901/gcallback.
4. Сохранить JSON клиента вне репозитория:
   ~/.config/sonicxboy-stats/google-oauth.json.
5. Запустить pnpm stats:auth, открыть http://localhost:8901/google/start и
   разрешить чтение Search Console.
6. Проверить pnpm stats:google, затем передать необходимые секреты в Vercel.
7. Для постоянного refresh token внешнее OAuth-приложение должно быть в режиме
   In production: тестовый режим ограничивает срок токена для этих scopes.

Запрашивается только https://www.googleapis.com/auth/webmasters.readonly.

Имеющийся импорт CSV/ZIP можно использовать для разового анализа без Cloud.
Он не обеспечивает автоматическое обновление и не должен подменять живой API.
Нефильтрованный экспорт всего домена не используется в отчёте портфолио.

## Проверка перед выпуском

    pnpm test
    pnpm build

Проверить RU/EN страницы в браузере, отсутствие переполнения на 390 px,
состояния без подключения Google и при сбое API, серверные заголовки кэширования,
а также отсутствие секретов в статических файлах сборки.

Выпускать только изменения статистики. В основной рабочей копии есть отдельные
неопубликованные изменения главной и блога.
